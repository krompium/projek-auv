Summary

Debug the on-drone Android detection pipeline end to end, prove its algorithms match real-world testing, then raise detection quality and runtime smoothness — correctness first.

Three concrete bugs are already confirmed by reading the current code, the largest being a tracking bug that compares normalized [0,1] box centers against a 150-pixel threshold, so every detection always matches the nearest track. This corrupts track IDs and the Firebase dedup that depends on them — the likely root of the "tracking not smooth" thread the project stalled on. The plan fixes correctness bugs, builds an offline harness to validate the TFLite pipeline against Colab/Roboflow ground truth, tunes detection thresholds from data, then adds inter-frame prediction and thermal-aware gating for smoothness. The web dashboard is out of code-inspection scope (its code is not in this repo) and is carried as a validation checklist plus deferred follow-up.

Problem Frame

The system (DJI feed → GPU YOLOv8n float16 → Firestore) runs stably at Dropped=0 and 30 FPS FPV, but the reported field symptoms — box lag, false positives, missed detections, Firebase over- and under-counting, unstable track IDs, thermal slowdown — point to correctness and validation gaps rather than raw stability. Two forces make debugging hard and shape this plan: the phone's USB is occupied by the RC (so Logcat is impractical — diagnostics must be file-based and offline), and the test device (Helio G99 / Mali-G57 MC2) is at its realistic inference ceiling (~200 ms/frame), so smoothness must come from prediction, not faster inference. The knowledge base (UAV_Waste_Detection_KnowledgeBase.md) is the origin document for prior decisions and the open tracking thread.

High-Level Technical Design

The pipeline is unchanged in shape; the plan repairs specific stages and inserts a prediction stage. The diagram marks where each unit lands. Prose in the Implementation Units is authoritative — the diagram only orients.

Key Technical Decisions

KTD1 Fix tracking in normalized coordinate space, one unit system throughout

Box centers from YoloDetector are normalized [0,1], but assignTrackIds() matches against MAX_DISTANCE = 150.0f pixels — so the guard never rejects a match. Rather than convert to pixels ad hoc, keep association in normalized space with a normalized threshold (e.g. ~0.05–0.10 of frame width). Single source of truth for units prevents the class of bug recurring.

KTD2 Letterbox preprocessing to match training-time input

getBitmap(640, 640) squashes the 16:9 feed into a square; YOLOv8 was trained on aspect-preserved letterboxed images, so the current input is distorted relative to training — a direct accuracy loss. Resize with aspect preserved and pad, then inverse-map output boxes. This is the highest-leverage detection-quality fix.

KTD3 Validate before tuning — build the offline harness first

Because Logcat is impractical (USB = RC) and thresholds were never data-derived, correctness must be proven against Colab/Roboflow ground truth before any threshold change. Tuning blind risks chasing a parsing bug with a threshold band-aid. The harness (U6) gates the accuracy work (U7, U8).

KTD4 Smoothness via prediction, not faster inference

The knowledge base establishes the Helio G99 is at its inference ceiling (~200 ms) and Dropped=0 already holds. Boxes freeze because the overlay only updates every ~400 ms. The lever is inter-frame interpolation/prediction (linear, or a lightweight per-track Kalman), not squeezing the model.

KTD5 Geo-grid peak aggregation as the dedup source of truth

Upload dedup currently keys only on trackId, which the tracking bug makes unreliable (over-count on churn, under-count on false merges). Move the source of truth to a geographic grid (~11 m via toFixed(4), matching the web dashboard's KDE/MAUP assumptions) recording the peak count per cell, so data integrity no longer depends solely on tracker stability.

KTD6 Keep float16 as the active runtime path; make int8 correct but opt-in

The active model is best_float16.tflite (float32 I/O, GPU-friendly). The int8 branch in bitmapToInputBuffer uses r + inputZeroPoint instead of the proper quantization formula — dormant today but a trap. Correct it and guard it behind explicit model selection rather than switching the default.

Milestone 2 — Correctness bug fixes
U2

Fix track-association coordinate-space mismatch

Goal
Make assignTrackIds() reject far matches by comparing normalized centers against a normalized threshold, restoring stable per-object track IDs.
Requirements
R1; unblocks R7, R10
Dependencies
U1 (to measure track stability before/after)
Files
app/src/main/java/com/dji/sdk/sample/internal/view/YoloDetector.java, new internal/view/YoloDetectorTrackingTest.java
Root cause: MAX_DISTANCE = 150.0f is compared against Math.hypot of normalized [0,1] centers (max ≈ 1.41), so the guard never fires and every detection greedily matches the nearest existing track.
Approach
  • Set the threshold in normalized units (start ~0.06 of frame diagonal; expose as a tunable constant).
  • Consider replacing greedy nearest-match with IOU-based association (the box already computes IOU) or greedy-by-ascending-distance to reduce ID swaps when objects are close.
  • Leave MAX_LOST_FRAMES semantics intact; verify color-by-trackId in OverlayView stabilizes as a side effect.
Test scenarios
  • Covers R1. Happy path: a track at (0.5,0.5) followed by a detection at (0.52,0.51) keeps the same ID across cycles.
  • Edge: two detections 0.5 apart do not collapse into one track; a detection 0.9 away spawns a new ID rather than stealing a distant track.
  • Edge: object lost for >MAX_LOST_FRAMES is pruned; reappearance gets a fresh ID.
  • Edge: empty detection list leaves tracker state consistent (lostFrames increment, pruning correct).
Verification
  • From U1 logs, activeTrackCount for a filmed stationary object stays ~1 across a 10 s clip instead of climbing.
U3

Letterbox preprocessing + inverse box mapping

Goal
Feed the model an aspect-preserved, padded 640² input and map output boxes back to the original frame, removing the squash distortion.
Requirements
R2; advances R8
Dependencies
U1
Files
app/src/main/java/com/dji/sdk/sample/internal/view/YoloDetector.java, internal/view/BaseFpvView.java, new internal/view/LetterboxTest.java
Approach
  • Capture at the source aspect (or full frame), then scale-longest-side + pad to 640² (gray pad), tracking scale and pad offsets.
  • In parseOutput, subtract pad and divide by scale before clamping to [0,1] of the original frame, so OverlayView mapping stays correct.
  • Keep the allocation off the hot path where possible; reuse buffers.
Test scenarios
  • Covers R2. Happy path: a synthetic 16:9 frame with a known box at frame center maps to a centered box after inverse transform (IoU ≥ 0.95 vs expected).
  • Edge: object at frame edge maps inside [0,1] without being clipped by padding.
  • Edge: square input (1:1) reduces to identity transform (no pad).
Verification
  • Visual: boxes sit tight on objects at the left/right edges of the FPV, not shifted inward; confirmed against U6 parity numbers.
U4

Concurrency & lifecycle hardening

Goal
Remove the frame-gate race and complete the tracker reset so state can't leak across sessions or threads.
Requirements
R3
Dependencies
U2 (reset must clear the corrected tracker state)
Files
internal/view/BaseFpvView.java, internal/view/YoloDetector.java, demo/camera/ObjectDetectionView.java
Approach
  • Replace volatile boolean isProcessingFrame with AtomicBoolean + compareAndSet(false,true) to gate the capture atomically.
  • Add a reset() to YoloDetector that clears trackedObjects and nextTrackId; call it from clearAllTracks() alongside uploadedTrackIds.clear().
  • Wrap CompatibilityList in try-with-resources; delete now-dead frameCount, videoWidth, videoHeight.
Test scenarios
  • Covers R3. Happy path: concurrent capture attempts while a frame is in flight → exactly one proceeds, others count as dropped.
  • Edge: clearAllTracks() resets both the upload set and tracker so the next detection starts at trackId 1.
  • Edge: rapid attach/detach of the view leaks no detector/thread (resources closed).
Verification
  • Bench a long session; U1 log shows no ANR/OOM and Dropped stays 0.
U5

Correct the int8 path + model/label consistency guard

Goal
Make int8 quantization mathematically correct and opt-in, and fail loudly when label count ≠ model output channels.
Requirements
R4
Dependencies
None (independent of U2–U4)
Files
internal/view/YoloDetector.java, app/src/main/assets/labels.txt, new internal/view/QuantizationTest.java
Latent bug: bitmapToInputBuffer writes (byte)(r + inputZeroPoint); correct int8 input is round(r/255f / inputScale) + inputZeroPoint. Dormant because the active model is float16, but it breaks any int8 switch.
Approach
  • Fix input quantization and confirm output dequant matches; keep best_float16.tflite as the default MODEL_FILE.
  • At load, read the output tensor's channel dim, compute expected classes = channels − 4, and assert it equals labels.size() (currently 1 = rubbish); surface a clear error toast + log on mismatch.
Test scenarios
  • Covers R4. Happy path: with the int8 asset, a fixed input yields dequantized outputs matching a reference within tolerance.
  • Edge: labels file with 2 lines against a 1-class model → load fails with an explicit message, not silent misparse.
  • Edge: float16 model path unaffected (regression guard).
Verification
  • Toggle to the int8 asset on the bench and confirm detections appear correctly, then revert default.
Milestone 3 — Validation against real testing

Offline parity & accuracy harness

Goal
Run the Roboflow test set through the on-device pipeline and compare against Colab/PC ground truth to prove the TFLite parsing, letterbox, and NMS are correct, and to produce precision/recall.
Requirements
R5, R6
Dependencies
U3, U5
Files
new internal/view/DetectionHarness.java (asset-image replay mode), new tools/parity_check.py, internal/util/MetricsLogger.java
Execution note: build this harness before tuning any threshold — it is the ground-truth oracle the rest of Milestone 3–4 depends on.
Approach

  • tools/parity_check.py runs the same .tflite (or the .pt) in Colab on the identical images, then computes per-box IoU, class agreement, and confidence delta vs the device dump.
  • Compute precision/recall/mAP@0.5 against Roboflow labels; export a short report.
Test scenarios
  • Covers R5. Parity: for ≥95% of test boxes, device-vs-Colab IoU ≥ 0.9 and class matches; confidence within ±0.05.
  • Covers R6. Accuracy: precision/recall reported per confidence threshold sweep (0.2–0.6).
  • Edge: an image with no rubbish yields zero device detections (no phantom boxes).
  • Diagnostic: any systematic coordinate offset (e.g. constant shift) is flagged as a parity failure, not averaged away.
Verification
  • Parity report shows no systematic offset; accuracy table is populated and archived under docs/.
U7

Threshold calibration + field stress-test protocol

Goal
Choose CONFIDENCE_THRESHOLD and IOU_THRESHOLD from the U6 sweep to minimize false positives without dropping real rubbish, and document a repeatable field test.
Requirements
R6, R8
Dependencies
U6
Files
internal/view/YoloDetector.java (constants), demo/camera/ObjectDetectionView.java (upload threshold), new docs/field-test-protocol.md
Approach
  • Pick the operating point from the precision/recall curve; align the detector threshold (0.35) and the upload threshold (0.40) deliberately rather than by accident.
  • Write a protocol covering altitude, speed, rotation rate, and occlusion cases that stress tracker drop and false positives.

Milestone 4 — Tracking smoothness & performance
U8

Inter-frame box interpolation / prediction

Goal
Smooth overlay boxes between the ~400 ms detection cycles so they follow objects instead of freezing then jumping.
Requirements
R7
Dependencies
U2 (stable IDs are a precondition for per-track prediction)
Files
internal/view/OverlayView.java, internal/view/YoloDetector.java (expose per-track velocity), new internal/view/InterpolationTest.java
Approach
  • Store last box + a velocity estimate per trackId; between detections, advance boxes on the overlay's own invalidate tick (linear first; upgrade to a small constant-velocity Kalman if needed).
  • Snap to the measured box when a fresh detection arrives to avoid drift accumulation.
Test scenarios
  • Covers R7. Happy path: a track moving at constant velocity is predicted within a small error at the mid-cycle tick.
  • Edge: a track that disappears stops being drawn within one cycle (no ghost box left behind).
  • Edge: a new detection snaps the predicted box to the measured position without a visible jump.
Verification
  • Visual: boxes track a walking person/object smoothly on the FPV; no stutter between cycles.
U9

Adaptive frame skip + motion/thermal-aware gating

Goal
Reduce sustained thermal load by skipping inference when the scene is static and adapting the capture interval to measured inference time, keeping Dropped=0.
Requirements
R9
Dependencies
U1
Files
internal/view/BaseFpvView.java, optional warm-up in YoloDetector.java
Approach
  • Derive MIN_CAPTURE_INTERVAL_MS from a rolling average of inferMs (from U1) instead of a fixed 400 ms.
  • Cheap frame-difference check: when successive frames are near-identical (static hover), lengthen the interval; restore on motion.
  • Optional one-time warm-up inference on a dummy bitmap at init to absorb shader-compile/DVFS jank.
Test scenarios
  • Covers R9. Happy path: under a static scene, inference frequency drops and logged temperature-proxy (inferMs creep) stays flat over a long run.
  • Edge: motion resumes → interval returns to the responsive value within one cycle.
  • Edge: adaptive interval never drops below the safe floor that would reintroduce dropped frames.
Verification
  • U1 log over a 10-min run shows inferMs creep reduced versus the fixed-interval baseline, Dropped still 0.
Milestone 5 — Firebase data integrity
U10

Geo-grid peak aggregation + offline persistence

Goal
Make upload record one aggregated point per real location and survive signal loss, so heatmap counts stop over/under-reporting.
Requirements
R10
Dependencies
U2 (stable IDs feed correct per-cell counts)
Files
demo/camera/ObjectDetectionView.java, internal/controller/DJISampleApplication.java (persistence init)
Approach
  • Key dedup on a geo-grid cell (~11 m via toFixed(4) on lat/lng), storing the peak simultaneous count per cell; update Firestore only when a cell's peak increases — matching the web dashboard's KDE/MAUP grid.
  • Enable Firestore offline persistence (local cache) so detections during signal loss queue and auto-sync on reconnect.

Test scenarios
  • Covers R10. Happy path: a stationary pile filmed for 10 s writes one aggregated cell record, not one per cycle.
  • Edge: two piles in adjacent grid cells produce two records; two detections in the same cell produce one with the peak count.
  • Error: offline during detection → record queued locally and synced after reconnect; no data loss.
  • Edge: GPS NaN/zero → nothing uploaded (guard preserved).
Verification
  • A bench flight with mock GPS yields Firestore counts that match the physical scene, and a forced-offline segment syncs on reconnect.

Scope Boundaries

In scope — the Android app pipeline (capture, preprocessing, inference, parsing/NMS, tracking, overlay), model/detection correctness and threshold tuning, on-device + Colab validation, and the Firebase upload/aggregation logic in ObjectDetectionView.
Deferred to follow-up — web dashboard code fixes (heatmap KDE, Haversine/MAUP clustering, temporal Calendar Boundary, reverse geocoding). The code is not in this repo; U10 aligns the mobile schema to the dashboard's grid assumptions, and a validation checklist is provided below, but code-level dashboard work waits until that code is shared.
Outside this effort — retraining or re-exporting the YOLOv8 model (U6/U7 tune thresholds and preprocessing around the existing weights; a retrain is a separate decision if accuracy stays short), and swapping the DJI SDK or camera architecture.

Web dashboard validation checklist (no code changes here):

  • Confirm the dashboard grid precision matches U10's toFixed(4) cell keying so mobile and web agree on "one location."
  • Verify heatmap intensity reads the aggregated peak count field, not a raw row count, once U10 ships.
  • Re-check temporal Calendar Boundary parsing against the new timestamp records after any format change.

Risks & Dependencies

Open · external
Web dashboard code unavailable. Dashboard-side fixes and full end-to-end heatmap validation can't be completed until that code is shared. Mitigation: U10 aligns the mobile write schema to the documented grid; dashboard work is explicitly deferred.
Watch · hardware
Inference ceiling on Helio G99. Performance headroom is limited (~200 ms/frame is near the floor). Smoothness relies on U8 prediction, not faster inference; U9 targets thermal creep, not throughput.
Watch · environment
Field validation needs an outdoor GPS lock and drone availability. 6+ satellites only lock outdoors after 30–60 s. The offline harness (U6) de-risks this by validating detection accuracy without a flight; only U7/U10 field steps need the drone.
Dependency · resolved
Ground-truth data exists. The TFLite model and a labeled test set are available on Roboflow, which makes the U6 parity/accuracy harness feasible without new labeling.
Watch · schema
Changing dedup/aggregation (U10) alters Firestore document shape. Existing waste_detections_v2 readers (the dashboard) must tolerate the peak-count field. Mitigation: additive fields, coordinate the change with the dashboard checklist above.
